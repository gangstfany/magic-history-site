# Magic History 四仓库迁移实施计划

Goal: 独立GitHub仓库、课程发布与首页隔离、原站不受修改。
Architecture: site通过校验origin/source的版本化postMessage加载apwh/art独立工作区；auth作为固定commit的发布依赖，仅在site明确更新版本时改变。四库独立Pages流程。
Tech Stack: 原生HTML/CSS/JS、Python静态构建、Node测试、GitHub Actions/Pages。

- [x] 备份与边界：锁定世界史cd44018、检查艺术史工作区与已提交资源，保持原仓库不变；本地创建四个同名目录及独立Git。
- [x] 账号仓库：提取auth模块与vendor SDK，保留callback路径语义，创建独立演示页/构建/测试、发布清单；site固定该提交，构建校验HEAD。
- [x] 艺术史仓库：提取最新已提交完整课程页面、公开依赖及相关验证，保留原始未提交草稿不上传；提供模块ready/resize协议、独立入口、来源说明及Pages工作流。
- [x] 世界史仓库：移动完整现有世界史工作区与构建源码；删除首页、账号和其他课程依赖；保留所有49链225环、学习卡、商路、练习；提供today-pick/readiness/height协议及构建验证。
- [x] 首页仓库：保留原首页视觉与导航；课程区域替换为独立iframe，由配置决定地址；Today’s Pick使用受控数据协议及纯文本渲染，点击发送打开命令；加入加载失败与重试、来源校验、限幅高度；账号采用固定SHA构建依赖。
- [x] 本地集成验证：四库独立测试、内容校验、跨端口真实跨来源页面检查、账号入口、Today’s Pick/因果链/商路/练习/艺术史入口；断言site无课程DOM/API读取，改课程不改变site及auth源码指纹。
- [x] 创建与发布：检查四个远端名是否存在，创建公开仓库（来源均原公开源码），独立main推送，启用各库Pages工作流；不触碰原站Pages。核对远端HEAD及部署状态。
- [x] 交付：四库地址、本地/新站入口、目录与改动归属表、必要认证回调白名单操作及未提交艺术史草稿范围；用户无需继续使用旧库课程分支提交。

执行顺序：独立账号/艺术史按边界分别实现；世界史与首页先确定协议再接通。新增功能用Node契约测试先失败再实现，网页操作用CUA核对。全部通过后各库提交，不推送任何原库分支。

完成说明：四库均已独立推送并成功部署。账号UI已验证，实际登录流程与新回调白名单未在无用户凭据情况下执行。跨来源本地嵌入和线上同来源不同仓库嵌入已核对；遗留艺术史未提交草稿明确保留原处。
